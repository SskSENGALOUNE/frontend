# QA report: ปรับ UX/UI แบบ mobile-first, ทดสอบ และหาบั๊ก

วันที่: 5 ต.ค. 2026 · ขอบเขต: `frontend/` (เขียนใหม่ทั้งหมด) และ `backend/` (แก้บั๊ก #1, #2)

## สรุป

- UI ใหม่เป็น mobile-first มี bottom tab bar พร้อมปุ่ม + ตรงกลาง (sidebar บนจอ ≥1024px) ทุกหมวดมีไอคอนและสี (lucide-react) และข้อความทั้งหมดเป็นภาษาลาว
- บันทึกรายจ่าย 1 รายการใช้ **3 แตะ + พิมพ์จำนวนเงิน** (นับจากหน้าไหนก็ได้) ถ้าอยู่ในหน้าบันทึกอยู่แล้วเหลือ 2 แตะ
- บั๊กที่รู้แล้ว 9 ข้อแก้ครบ เจอเพิ่มระหว่างทำอีก 5 ข้อ แก้แล้ว 4 ข้อ อีก 1 ข้อเป็นเหตุการณ์ที่ต้องให้เจ้าของระบบตัดสินใจ (ดู F11)
- Test ผ่านทั้งหมด: Go 2 packages, unit 20, e2e 29

## Usability

### จำนวนแตะต่องาน (มือถือ)

| งาน | UI เดิม | UI ใหม่ |
|---|---|---|
| บันทึก 1 รายจ่าย | 4 แตะ + พิมพ์ (เมนู → เปิด dropdown → เลือก → บันทึก) | **3 แตะ + พิมพ์** (ปุ่ม + → แตะไอคอนหมวด → บันทึก) หรือ 4 แตะไม่ต้องพิมพ์ ถ้าใช้ปุ่มจำนวนลัด |
| บันทึก 5 รายจ่าย | 14 แตะ + พิมพ์ 5 ครั้ง | **11 แตะ** + พิมพ์ 5 ครั้ง |
| ดูว่าเดือนนี้ใช้หมวดอาหารไปเท่าไร | 0 แตะ แต่ต้องเลื่อนหา | 0 แตะ อยู่ในการ์ด "ໃຊ້ຫຼາຍສຸດ" พร้อม % และไอคอน |
| ตั้งงบ 1 หมวด | 2 แตะ + พิมพ์ | 3 แตะ + พิมพ์ (แลกกับ sheet ที่โชว์ยอดที่ใช้ไปแล้ว) |

หมวดที่ใช้บ่อย 4 อันดับแรกขึ้นแถวบนสุดของ grid อัตโนมัติ (จำไว้ใน localStorage)

### Touch target และ contrast
- ปุ่ม/ลิงก์/ช่องกรอกที่มองเห็นในหน้าหลักทุกตัวสูง ≥44px (ตรวจอัตโนมัติด้วย e2e) ก่อนแก้มีชิปสูง 36px, ปุ่มเลื่อนเดือน 40px, ช่องจำนวนเงิน 43px
- Contrast (คำนวณจาก token ทุกคู่ข้อความ/พื้นหลัง): light ต่ำสุด 4.6, dark ต่ำสุด 6.3 ผ่าน AA ทุกคู่ ก่อนแก้มีสีไอคอนหมวด 3 สีที่ 4.19–4.31 ใน light
- Keyboard: ทุกปุ่มมี focus ring, sheet ใช้ `<dialog>` แบบ modal (focus อยู่ใน sheet, กด Esc ปิดได้), ปุ่มที่มีแต่ไอคอนมี `aria-label` ภาษาลาว
- รองรับ `prefers-reduced-motion`, dark mode ทุกหน้า, safe-area ของ iPhone

## การตัดสินใจที่ทำเอง

- **รายรับบันทึกทีละรายการ** ตะกร้าหลายรายการใช้กับรายจ่ายเท่านั้น เพราะ `POST /expenses` รับแค่รายจ่าย และรายรับมักมาทีละก้อน
- **หน้าบันทึกเป็นแบบเต็มจอ** (ซ่อน bottom bar มีปุ่ม X) เพื่อให้ปุ่มบันทึกติดล่างจอและอยู่ใกล้นิ้ว
- **กราฟภาพรวมแสดงรายจ่ายรายวันอย่างเดียว** เพราะรายรับมักเป็นก้อนใหญ่ไม่กี่วัน ถ้าใส่ไว้ในกราฟเดียวกันจะทำให้แท่งรายจ่ายเตี้ยจนอ่านไม่ออก ส่วนรายรับแสดงในการ์ดด้านบน
- **ระหว่างตรวจ session หน้าก็เริ่มโหลดข้อมูลเลยถ้ามี token** ถ้า token ใช้ไม่ได้ จะได้ 401 แล้วกลับไปหน้า login เหมือนเดิม
- **สีหมวดเก็บเป็นชื่อ palette** (`green`, `teal`…) ไม่ใช่ hex เพื่อให้มีค่าที่อ่านได้ทั้ง light และ dark ถ้าหมวดไม่มีสี ระบบจะเลือกสีจากชื่อหมวดให้คงที่
